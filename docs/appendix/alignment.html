首页 / 附录 / 能力综合对照

本页面向使用者，全维度对照 opencode 定制版与内部 Agent 运行时「参考实现」：哪些能力直接对齐、哪些以其他方式等价实现、哪些存在差异（附替代方式）。

判定图例：✅ 对齐（含源码级确认）· 🔵 等价实现（路径不同、行为可达）· 🟡 差异/缺口（附替代方式）。语气中性，不涉内部部署细节。

一、总览（23 维度）

# 维度 判定 参考实现 → opencode 一句话对照
1 安装与更新 🔵 多平台一键脚本 → bootstrap.sh（拉取+部署+提示）+ init.sh（幂等 / 覆盖策略 / 备份），定制版源码编译
2 界面形态 🔵 终端 + Web 工作台（多面板）→ TUI 主线 + opencode web（server + Web 界面）/ serve（headless）
3 模型与档位 🔵 轻量 / 主力 / 视觉虚拟档位 → model / small_model + model: small 别名 + 模型选择器
4 网关与 Provider 🔵 网关免配置绑定 → provider 配置 + 模型目录自动发现
5 子代理 ✅ 四类子代理 + 并发上限 4（1-8）→ 五类子代理 + subagent_max_concurrency 4（1-8）
6 编排模式 ✅ single / parallel / chain / refine 全对齐
7 计划引擎 ✅ 四层规划 + DAG 子计划全对齐
8 任务与 Todo ✅ goal / bug 类型 + 活跃任务锚点注入
9 技能系统 ✅ 加载 + 使用统计 + 触发条件（21 技能 + 插件技能 3）
10 工具能力 ✅ 16 个原生工具覆盖参考实现工具域
11 工作流 ✅ 12 节点 DAG 全对齐
12 评估 ✅ 8 类 gate + 评估策略 + trials（消随机）
13 上下文工程 ✅ AGENTS 扫描 / SYSTEM.md / APPEND_SYSTEM.md（源码级确认）
14 记忆与场景 ✅ memory + workscene（含 requirements 分类）
15 Token 经济 ✅ 分档 / 隔离 / 截断 / 压缩 / 并发上限 / 度量 / 缓存 全谱对应
16 工作区隔离 ✅ worktree create / merge / remove（守护语义对齐）
17 凭据与权限 🔵 四档审批模式 → per-tool allow/ask/deny 等价；加密 env 对齐
18 通知与后台 ✅ 后台任务退出码 + 桌面通知 + 飞书通知三件套
19 资产分发 ✅ 5 类资产 + meta + 三层查找 + 镜像 / 搜索 / 依赖解析
20 文档与知识 ✅ 知识库 → 25 页文档站 + 双册仓库文档（公开手册 + 内部补充）
21 多工作区托管 🟡 中心 daemon（注册 / 托管 / 自启）→ 无对应；serve + systemd 自行编排
22 专用 Agent 🟡 业务管线专用 Agent → 未对应（按需自建）
23 反馈上报 🔵 远程反馈系统 → /feedback + 可选 webhook（默认本地保存）

二、分组明细

安装与界面

参考实现能力 opencode 实现 对齐方式
多平台一键安装 bootstrap.sh（拉取 + 部署 + 隐私提示）+ init.sh（初始化 / 编译 / 自检） 覆盖（Linux 主线）
图形界面 opencode web（启动 server 并打开 Web 界面）；opencode serve（headless，供 API / 桥接） 等价（形态不同）
密钥加密存储 env-store（AES-256-GCM）+ secrets.env（bashrc / systemd 注入） 覆盖
更新与重编译 git pull + opencode init --build；init.sh 幂等可重跑 覆盖

模型与网关

参考实现能力 opencode 实现 对齐方式
模型分档（轻量 / 主力 / 视觉） small_model（轻任务与子代理）+ model（主力）+ model: small 别名；视觉直连多模态模型 等价（无虚拟档位）
模型目录自动发现 provider 模型发现（/models 端点）+ 模型选择器 tabs 等价
网关免配置接入 provider 字段手工配置（{env:XXX} 引用凭据） 等价（无自动绑定）

资产与分发

参考实现能力 opencode 实现 对齐方式
资产 5 类 + meta.json + 三层查找 asset-manager（pull / install / push / status / list / info / export / run / setup / search / mirror / 依赖解析） 覆盖 + 增强
资产镜像（本地源） asset list/pull/info/run --mirror <dir>，优先级：项目级 > 镜像 > 远程 补齐
资产搜索 asset search <关键词>（名称 / 描述 / 标签模糊匹配） 补齐
依赖解析 asset pull @launcher/xxx 按 meta.json 的 requires 自动拉依赖 补齐

三、本次新增能力

能力 是什么 落点 / 开关
子代理小模型 agent frontmatter 写 model: small → 解析为 small_model（解析不到回退父模型）；轻量探索自动走快档 .opencode/agent/explorer.md 已默认挂载
子代理并发上限 subagent_max_concurrency 限制同时运行的子代理数，防并发风暴；进程内全局生效 opencode.json（默认 4，范围 1-8）
worktree merge 与守护 git-worktree 新增 merge：rebase → 预检 → fast-forward → 可选 cleanup，冲突自动 abort 不动主树；remove 在树脏或分支未合并时拒绝删除 git-worktree 工具
评估 8 类 gate gate 类型扩到 8 种，新增 file_contains / command_passes / latency_under / turns_under / cost_under（后三者把「答对但慢/贵/啰嗦」纳入回归） .opencode/evals/ 场景 YAML
后台任务退出码 + 通知 后台任务完成时记录 exit_code / finished_at 并落盘，完成时发桌面通知（notify-send，可关） background-task 工具
技能 debug / goal 升级 debug 强化「证据分级 + 卡壳协议」；goal 强化「信心标注 + 缺口即问」 .opencode/skills/{debug,goal}/SKILL.md

新增能力速览（一句话）

  • 省 token：探索走小模型（model: small），并行有上限（subagent_max_concurrency）；
  • 更安全：worktree 合并走 fast-forward 且冲突自动 abort，删除有守护；
  • 可度量：评估从「答对否」扩到「快 / 省 / 简洁否」；
  • 可观测：后台任务带回退出码并主动通知；
  • 更诚实：调试与目标澄清技能强制区分事实与假设、标注信心。

四、以「其他方式」实现的差异点

以下能力参考实现有独立机制，定制版通过配置层等价实现（行为可达，实现路径不同）：

参考实现机制 定制版等价实现 说明
LSP custom_checkers lifecycle-hooks 自定义检查器 编辑后运行匹配的检查命令，结果回注工具输出（模型可见）
每轮感知活跃任务 lifecycle-hooks 活跃任务注入 压缩时把 in_progress 任务作为工作锚点注入会话
/feedback 远程系统 /feedback + webhook 环境变量 默认保存到本地；配置 webhook 后 fire-and-forget 上报
技能路径限定 / when_to_use 项目级 skills 目录 + description 触发 技能放对目录 + 描述写清触发条件即可

五、差异与缺口

缺口 说明 替代方式
多工作区托管 无中心 daemon（注册 / 托管 / 开机自启） serve 单实例 + systemd 单元自行编排
模型虚拟档位 无「轻量 / 主力 / 视觉」三档位绑定 small_model + model: small 近似轻量档；视觉选多模态模型
Web 工作台面板 面板构成与深度未逐一比对 TUI 主线；todo / plan 工具近似「待办计划」
快捷启动生成器 无引导式「Browse → Install」生成启动脚本 资产 pull + @launcher/* + asset run
网关免配置绑定 无首用绑定与目录自动刷新 provider 手工配置 + 模型目录发现
平台覆盖 一键脚本面向 Linux macOS / Windows 按需补平台分支或手动步骤

六、边界说明

  • 对齐结论：参考实现功能点在维度级均有对应（✅ 15 / 🔵 6 / 🟡 2），缺口均附替代方式、按需补充。
  • 内部资产与公开资产分离：内部专用资产与公开通用资产分开管理，本仓库只承载公开通用能力；受隐私红线约束，含组织信息的文档不进入公开仓库。
  • 命名：文档统一用「参考实现」指代内部 Agent 运行时，不出现内部域名、主机名与人员信息。
  • 工具命名约定：单文件单工具（tool({ description, args, execute })）+ CLI 入口（bin/<name> 由 init.sh 生成）。
