首页 / 核心能力 / 技能系统

技能（skill）是按需注入的操作指南：系统提示里只放「名称 + 描述」，命中任务时才把正文加载进上下文。这样技能再多，每轮的固定成本也不变（见 省 token 与上下文管理）。

一、技能是什么

一个技能 = 一个 SKILL.md（目录名前缀无强制要求），放在 .opencode/skills/<name>/。它由三层「渐进式披露」组成：

层 内容 何时进入上下文
元数据 frontmatter 的 name + description 始终在系统提示中（约百字）
正文 SKILL.md 的 Markdown（建议 < 500 行） 技能被触发时加载
资源 scripts/ / references/ / assets/ 用时才读，脚本可直接执行

匹配与加载都靠 description——所以描述要同时说清「做什么」和「何时用」。

二、加载机制

  • 按需加载：内置 skill 工具按名称加载，触发时返回正文 + base 目录 + 采样文件列表；
  • 权限门禁：加载会经过 skill 权限询问（TUI 中按当前权限模式决定是否确认）；
  • 路径来源：项目级技能放 <项目>/.opencode/skills/（只在该项目生效）；全局经 skills.paths 加载，包含随插件分发的技能；
  • 目录扫描即生效：新增技能目录即被发现，/reload 可手动刷新。

task 工具拉起的子代理同样能加载技能——所以「探索/实施/审查」各自可以挂上对应的技能。

定制版内置 35 个技能（name 带 sk_ 前缀的为自带短标识）：

docx / pdf / pptx / xlsx / skill-creator 与新增的 14 个通用技能（canvas-design … discernment-nudge）来自 Anthropic 公开技能库，均通过资产库分发（asset pull @skill/<name>）。

四、写一个自定义技能

4.1 frontmatter 字段

---
name: my-skill            # 可省略：省略时取文件/目录名
description: 一句话说清做什么 + 何时触发（"当 X 时使用…"）
slash: false              # 可选：是否作为斜杠命令暴露
---

正文：分步骤的操作指令、检查清单、输出模板……
  • description 是触发的主要依据，把「何时用」写进描述，而不是正文；
  • name 省略时由文件名/目录名推断；
  • 其余自定义字段（如 when_to_use、version、metadata）可保留，但触发匹配只认 description。

4.2 目录结构

my-skill/
├── SKILL.md          # 必需：frontmatter + 指令
├── scripts/          # 可选：确定性/重复任务的脚本
├── references/       # 可选：按需读入的长文档
└── assets/           # 可选：模板、图标、字体

4.3 创建流程

用 skill-creator 技能，或 asset new @skill/<name> 生成模板后编辑 SKILL.md。三个要点：

  1. 保持 SKILL.md 精炼——接近 500 行就该拆到 references/；
  2. 指令用祈使句，明确输出格式；
  3. 描述要"敢触发"——偏窄的描述会导致技能「该用而没被用」。

五、使用统计（skill_usage）

lifecycle-hooks 在每次 skill 工具加载时自动记录，写入 ~/.config/opencode/skill-usage.json（对齐「参考实现」的 skill-usage.json）：

skill-usage list              # 按使用次数降序列出（含最后使用时间）
skill-usage list --min 5      # 只看使用 >= 5 次的
skill-usage clear             # 清空统计

用途：识别高频技能（保留）、长期未用技能（可归档/裁剪）。

六、debug / goal 的升级要点

两个核心技能刚做过强化，把「诚实」与「止损」写成硬约束：

技能 升级点
sk_debug 证据分级：每条信息标 [FACT] / [HYPOTHESIS] / [UNKNOWN]；卡壳协议：连续 2+ 轮无新 [FACT] 等条件即停止深挖，带「已排除清单 + 具体 UNKNOWN」升级用户
sk_goal 信心标注：目标/范围/约束/验证/输出逐项标 [HIGH] / [MEDIUM] / [LOW]；2+ 项为 [LOW] 时必须先问用户，绝不把猜测包装成高信心

配套纪律：信心分级递进（低 → 中 → 高），没排除替代方案就跳到「高」要警惕确认偏差；同一操作连续失败 3 次即停并上报。方法论详见 快速定位问题。

七、落地清单

  1. 先看描述再看正文——用 description 判断该不该触发；
  2. 一个技能一件事——「分析模块 X 的认证流程」而非「分析整个项目」；
  3. 正文精炼 + 资源分层——大材料放 references/，脚本放 scripts/；
  4. 定期用 skill-usage 复盘——低频技能考虑归档；
  5. 提交前过安全与规范技能——code-review-security + commit-convention。

技能与插件、资产的关系见 插件与扩展；技能依托的编排能力见 子代理与编排。
