首页 / 核心能力 / 自定义工具

定制版在 .opencode/tool/ 内置 16 个自定义工具，随会话自动注册——对话中让 AI 直接调用即可，多数还提供等价的 CLI wrapper（不经过 LLM）。它们把团队需要的运行时能力（计划、编排、统计、安全、通信）沉淀为可复用的原生工具。

一、调用方式

入口 说明
对话内 让 AI 调用工具（如「用 plan 创建计划」），由模型决定参数
CLI wrapper init.sh 为多数工具生成 ~/.config/opencode/bin/<name>，可直接在终端调用
TUI 命令 部分工具有对应的斜杠命令（见 命令速查）

.opencode/tool/*.ts 由 opencode 目录扫描自动注册，无需在配置里声明；新增文件后 /reload 即可生效。

带 CLI 入口（可直接在终端调用、不经过 LLM）的工具：

asset list / pull / install / setup / run / bin / push / export / status   # 资产
plan init / write / sub / status / run / update            # 计划
privacy scan / git / mask / words                          # 隐私
skill-usage list / clear                                   # 技能统计
feishu-notify send "<内容>" [--title 标题]                 # 飞书通知
asset new @type/name                                       # 新建资产模板

二、按能力分组

编排与执行

工具 一句话 关键操作
background_task 长命令后台执行，日志落盘 + 完成通知 start -- <命令> / list / output <id> / stop <id>
git_worktree git worktree 沙箱隔离开发 create --branch <名> / list / remove <path>
cron 定时提醒记录（跨会话上下文注入） create <cron> <内容> / list / delete <id>

计划与任务

工具 一句话 关键操作
plan 计划引擎：四层规划 + DAG 子计划依赖 init / write <id> <section> / sub / status / run / update
task_manager 任务管理：状态流 + 依赖 + 活跃任务注入 create <标题> [--type goal\|bug] / update <id> --status / list / get <id>
todo Markdown todo（goal / bug，跨会话） add title="…" type=<goal\|bug> / list / activate slug=…

详见 计划与 Todo。

流程与质量

工具 一句话 关键操作
workflow_runner DAG 工作流引擎（12 种节点） list / validate <名> / run <名> key=value
eval_runner Agent 质量评估（真实执行 + 反馈循环） init -g <组> / run -g <组> / report / compare / analyze / baseline / validate

详见 工作流。

知识与场景

工具 一句话 关键操作
memory MEMORY.md 自动记忆（索引 + 主题文件） list / add <标题> / refresh <slug> / activate <slug>
workscene 工作场景知识库（参考知识 + 场景记忆） init / create / activate / status / show / find / archive / memory

资产分发

工具 一句话 关键操作
asset_manager 从远程 Git 仓库拉取/推送/部署/运行资产 list / info / pull / install / bin / push / status / search / setup / run / export
new_asset 创建资产模板（agent / skill / tool / launcher / plugin） 让 AI 调用，参数 asset_ref（如 @agent/myagent）

安全与隐私

工具 一句话 关键操作
privacy 敏感信息扫描 / 脱敏 / 敏感词清单管理 scan <path> / git / mask "<文本>" / words list\|add\|delete
env_store AES-256-GCM 加密环境变量存储 set <KEY> <value> / list / delete <KEY>

观测与通信

工具 一句话 关键操作
skill_usage 技能使用统计（lifecycle-hooks 自动记录） list [--min N] / clear
feishu_notify 通过 oc-lark 发飞书通知（授权 / 结果推送） send "<内容>" [--title 标题]

TUI 侧另有前端命令 /asset_manager（交互式 ✅/⬜ 列表，不经 LLM）——它是插件而非工具，见 插件与扩展。

三、几个易混点

说明
todo vs 内置 todowrite todo 落盘跨会话，todowrite 只在会话内（见 计划与 Todo）
task_manager vs todo task_manager 带状态流与依赖、活跃任务自动注入；todo 是 markdown 锚点
asset_manager vs asset CLI 同一个资产系统的两种入口：工具（经 LLM）/ CLI wrapper（不经 LLM）
memory vs workscene memory 是用户画像/习惯；workscene 是领域知识库与场景记忆

四、典型组合

工具很少单用，几个常见的组合套路：

场景 组合
复杂重构 plan（四层规划 + 子计划）→ 委派子代理实施 → workflow_runner 跑测试 → privacy 提交前扫描
长时间构建/测试 background_task start 启动 → 继续干别的 → 完成后桌面通知 / output <id> 取结果
隔离实验分支 git_worktree create 建沙箱 → 在其中开发 → 验证通过后再合回主干
客户问题闭环 customer-bug 技能驱动：读飞书表 → feishu_notify 通报 → Jira/Gerrit CLI → 关单
例行发布 workflow_runner run commit-flow 或 jira-submit-close，把固定步骤一次跑完

五、工具输出与上下文

工具产生的大输出是上下文成本的主要来源，定制版对此有统一约束（见 省 token 与上下文管理）：

  • 输出截断：超过 tool_output.max_lines / max_bytes 的结果写文件 + 保留头尾预览；
  • 后台落盘：background_task 的输出写 .opencode/tasks/<id>.log，只回传退出码与通知；
  • 只读结论：委派子代理时只回收最终文本，过程不进入主上下文。

六、落地清单

  1. 长命令一律进后台——构建、全量测试、监控用 background_task，输出落盘不占上下文；
  2. 加密而非明文——密钥用 env_store，别写进 .bashrc（见 凭据与权限）；
  3. 提交前跑 privacy——privacy git 等价提交前扫描；
  4. 复杂任务先 plan——四层写全再执行；
  5. 统计复盘——skill_usage 与评估门禁一起看，指导裁剪与优化。
