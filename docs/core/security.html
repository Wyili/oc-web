首页 / 核心能力 / 凭据与权限

凭据泄露是 Agent 工具链最现实的风险。opencode 定制版把「凭据」与「权限」拆成三条独立防线：密钥集中存储（不落 git）+ 权限模式控制操作 + 隐私门禁拦截提交。三者叠加，保证密钥与内网信息既进不了模型上下文，也进不了版本库。

一、密钥存哪里

所有密钥/凭据统一存 ~/.config/secrets.env（0600，非 git），由 ~/.bashrc 顶部注入环境变量，systemd 服务通过 EnvironmentFile 引用。

⚠️ 不要在 ~/.bashrc 直接写密钥——bashrc 是 644 明文、同组可读，且 systemd 服务不加载 bashrc。密钥一律进 secrets.env。

文件格式（纯 KEY=value 一行一个，不要 export 前缀、不要引号）：

OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx
ENTERPRISE_API_KEY=xxxxxxxx
JIRA_TOKEN=xxxxxxxx
入口 操作
TUI 命令（推荐） /secrets 查看指引，或对话中让 AI 写入
编辑文件 nano ~/.config/secrets.env
交互式引导 ./init.sh --prompt-secrets

二、注入机制（谁从哪里读）

使用方 读取方式
交互式终端（opencode CLI 等） ~/.bashrc 顶部 set -a; source ~/.config/secrets.env; set +a（set -a 自动导出为环境变量）
systemd 用户服务 EnvironmentFile=-/home/<user>/.config/secrets.env
opencode 运行时 opencode.json 的 {env:XXX} 引用环境变量 
# 当前会话手动加载（新终端自动加载）
set -a; source ~/.config/secrets.env; set +a

bashrc 交互守卫陷阱：~/.bashrc 开头有 case $- in *i*) *) return;; esac，非交互 shell 会提前 return。所以 source secrets.env 必须放在守卫之前，否则脚本/cron 等非交互场景拿不到变量。

三、加密存储（env-store）

除明文 secrets.env 外，还提供加密存储（AES-256-GCM）：对话中让 AI 调用 env_store 工具。

操作 说明
env_store set <KEY> <value> 加密写入，值以密文落盘
env_store list 列出变量名（值掩码显示 KEY=****）
env_store delete <KEY> 删除变量
  • 实现：aes-256-gcm，随机 12 字节 IV + 认证标签（tag），密文以 { iv, tag, value } 结构存 ~/.config/opencode/secrets.enc；主密钥存 ~/.config/opencode/.masterkey（首次使用自动生成 32 字节随机密钥，base64 编码）。
  • 用途：需要比明文文件更强保护、或不想让值以明文出现在磁盘时使用。

四、权限模式

opencode.json 的 permission 字段（或启动时 --mode）控制操作审批粒度：

模式 说明
trust 自动批准所有操作
balanced 平衡：常见操作自动批准，危险操作确认
strict 严格：每次操作确认
accept-edits 自动接受编辑
启动参数 opencode --auto 自动批准未被显式拒绝的权限
  • 子代理可单独声明权限（如 explorer 只读："*": deny + read/glob/grep: allow），子代理权限从父会话派生合并；
  • 每次工具调用都会写审计记录（~/.config/opencode/audit.log），授权询问也会被审计。

五、隐私门禁（privacy 工具）

把「隐私红线」从规则升级为可调用工具，提交/发布/导出/对话前统一扫描与脱敏：

privacy scan <path>          # 扫描文件/目录中的敏感信息（内置模式 + 敏感词清单）
privacy git                  # 检查暂存区（等价 pre-commit 逻辑）
privacy mask "<文本>"        # 脱敏输出（API key / token / 私钥打码）
privacy words list           # 敏感词清单
privacy words add "<正则>"   # 添加敏感词
privacy words delete <序号>  # 删除敏感词

内置敏感模式：

类别 匹配
API Key sk-…
GitHub Token ghp_ / gho_ / ghu_ / github_pat_
AWS Access Key AKIA…
私钥块 -----BEGIN … PRIVATE KEY-----
环境变量密钥赋值 TOKEN/SECRET/PASSWORD/API_KEY/… = <值>
长 Base64 串 ≥ 40 位 base64

privacy scan 输出命中位置，并给出脱敏后的安全内容（前 4 位 + *** + 末 3 位）。

六、钩子门禁（sensitive-scan.sh）

提交前拦截由 git hooks + 一个共用门禁脚本完成，脚本为 ~/.config/opencode/sensitive-scan.sh（本机非 git 文件，opencode 与资产发布 githooks 共用同一逻辑与清单）：

hook 调用 行为
.husky/pre-commit sensitive-scan.sh staged 扫描所有暂存文件（git show :<file>），命中即阻止提交
.husky/commit-msg sensitive-scan.sh message <msg-file> 扫描 commit message，命中即阻止
  • 脚本合并「内置模式」与「本机敏感词清单」；
  • 本机敏感词清单：~/.config/opencode/sensitive-patterns.txt（非 git，每行一个正则，# 与空行忽略）；
  • 未找到门禁脚本时跳过检查并告警（不阻断，但存在漏检风险，需确保 init.sh 已执行）。

七、隐私红线（最高优先级）

  • 密钥 / 内网地址 / 主机名 / 人员信息一律不进 git：仓库内 provider 的 baseURL 用占位符、apiKey 用 {env:XXX} 引用；
  • 敏感配置放 ~/.bashrc 或 ~/.config/opencode/（非 git），代码通过环境变量注入；
  • 提交/发布/导出前统一 privacy git / privacy scan；
  • 规则详见 .opencode/AGENTS.md「隐私红线」。

八、备份与迁移

# 备份（secrets.env 与 .masterkey 会一起打进去）
tar -czf ~/opencode-config-backup-$(date +%Y%m%d).tar.gz -C ~/.config/opencode .
# 恢复
tar -xzf ~/opencode-config-backup-*.tar.gz -C ~/.config/opencode
chmod 600 ~/.config/secrets.env ~/.config/opencode/.masterkey

迁移后自检：opencode debug config 确认所用 provider 的 apiKey 非空；opencode run "回复ok" --model <provider/model> 返回内容即成功，报 401 则回查密钥是否配置/是否 source。

九、落地清单

  1. 密钥只写 secrets.env（纯 KEY=value，0600），不写 bashrc；
  2. 改完密钥开新终端，或 set -a; source …; set +a；
  3. 危险项目用 strict/balanced 权限模式，探索类子代理用只读权限；
  4. 提交前跑 privacy git；敏感词沉淀进 sensitive-patterns.txt；
  5. 换机 / 重装前 init.sh --backup，还原后重跑密钥自检；
  6. 见 模型配置 的 provider 脱敏写法，与本文配合使用。
