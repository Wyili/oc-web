首页 / 核心能力 / 工作场景

场景（workscene）是领域知识库域：它不是对话历史，而是可以跨会话检索、逐次沉淀的领域知识 + 场景记忆。一句话——Agent 选谁做（代理）、怎么做（提示词），场景提供「做什么」的领域上下文。

一、场景由什么组成

一个场景就是一个目录，三部分组成：

组成 位置 作用
定义 scene.md frontmatter（name / description / reminders）+ 场景说明正文
场景记忆 memory/MEMORY.md 该场景的持久记忆条目（workscene memory）
参考知识 reference/* 可检索的知识文档（workscene find）
  • scene.md 的 reminders 字段可注入提醒；还支持可选的 model 字段，为指定子代理覆盖模型（效果同 agent frontmatter 的 model）。
  • 切换场景 = 切换 AI 可检索的知识库与记忆域，不是切换对话。

二、目录结构与 config.json

场景文件位置：<项目>/.opencode/workscenes/<name>/。config.json 记录 default_scene（当前激活场景）与 visible_scenes（可见场景列表）：

.opencode/workscenes/
├── config.json                 # { default_scene, visible_scenes }
├── default/                    # 默认场景
│   ├── scene.md                # 场景定义
│   ├── memory/MEMORY.md        # 场景记忆
│   └── reference/
│       ├── architecture/       # 架构知识
│       ├── bugfixed/           # 问题修复记录
│       ├── research/           # 调研结论
│       └── requirements/       # 需求
└── .archive/                   # 归档场景（archive 操作落点）

config.json 示例：

{
  "default_scene": "default",
  "visible_scenes": ["default"]
}

opencode init-project 会生成 workscenes/default/ 骨架；workscene init 等价地在当前项目补齐 config.json + default/ 目录树。

三、四类参考知识

reference/ 按用途分四类，find 时可按类别收窄：

分类 放什么 典型内容
architecture 架构与决策 目录结构、模块边界、关键设计取舍
research 调研结论 能力清单、外部方案对比、结论沉淀
bugfixed 问题修复 症状 → 根因 → 修复（避免重蹈覆辙）
requirements 需求 需求描述、验收口径、约束

四、workscene 工具操作

workscene 是 .opencode/tool/workscene.ts 注册的自定义工具，在会话中让 AI 调用（也可用 /workscene <操作>）：

操作 参数 说明
init — 初始化 config.json + default 场景目录树
create name [--description] 创建场景（并把新场景设为当前 default_scene）
status — 列出所有场景、当前场景、当前场景文件树
activate name 切换当前场景（写回 config.json）
show [name] 显示场景 scene.md（默认当前场景）
find query [--category ...] 在当前场景 reference/ 中检索
archive name 归档场景到 .archive/<name>-<时间戳>/，并从可见列表移除
memory add <text> / list 追加/列出当前场景记忆（memory/MEMORY.md）

要点：

  • create 若目录已存在则不覆盖 scene.md，但会更新 config.json；
  • archive 后若归档的是当前场景，default_scene 会回退到 visible_scenes 的第一个（否则回退 default）；
  • activate 的场景不存在会报错，提示先 create。

五、find 的检索语义

  • 检索范围：当前场景的 reference/（不含 memory/）；
  • --category 可取 research / architecture / bugfixed / requirements，收窄到子目录；
  • 只匹配 reference/ 下的 .md 文件，逐行做不区分大小写的子串匹配；
  • 命中时返回带上下文行的结果：目标行以 >>> 标记，前后各带一行，格式为 相对路径:行号: 内容。

这让「当前场景里有没有关于 X 的结论」变成一次低成本查询——先 find 拿线索，再按行号定向读文档。

六、场景记忆 vs 全局记忆

两套记忆互不干扰，按「知识属于谁」选择：

维度 场景记忆（workscene memory） 全局自动记忆（memory 工具）
位置 <项目>/.opencode/workscenes/<name>/memory/MEMORY.md ~/.config/opencode/MEMORY.md + memory/<topic>.md
作用域 当前项目的当前场景 当前机器的全部会话
适合 与该项目领域强相关的结论 稳定的个人偏好、通用解法、架构决策

七、提示词 / 场景 / 代理的关系

概念 是什么 定义位置 作用
代理 agent 执行角色（coordinator / explorer / executor / evaluator / spawn / task-planning） .opencode/agent/*.md 决定谁做：prompt、可用工具、模型、模式
项目上下文 项目级行为指令 .opencode/AGENTS.md 每次会话自动加载（规范/命令/隐私红线）
技能 skill 按需注入的步骤指令 .opencode/skills/*/SKILL.md 匹配任务时加载详细步骤
场景 scene 领域知识 + 记忆 .opencode/workscenes/<name>/scene.md 提供做什么的领域上下文，持久化知识

一句话：init-project 搭骨架 → 代理选「谁做」、技能/提示词定义「怎么做」、场景提供「做什么」的领域知识。

八、一个使用示例

假设在做一个「认证改造」项目，场景名 auth：

create    workscene create auth --description "认证模块领域知识"
          → 生成 .opencode/workscenes/auth/，并把当前场景切到 auth

沉淀     把关键设计写进 reference/architecture/「会话与 token 边界」；
          把一次踩坑写成 reference/bugfixed/「刷新令牌竞态」

复用      新会话先 workscene find "token" → 命中上述文档的上下文行，
          再按 相对路径:行号 定向读取，避免重新探索

记忆      workscene memory add "本项目的 token 有效期统一为 15 分钟"

归档      项目结束后 workscene archive auth

这样，启动场景是新建项目骨架 + 初始化场景；随后每次「查历史结论 → 定向读文档 → 沉淀新结论」都发生在同一个知识域里。

九、落地清单

  1. 新建项目先初始化场景：opencode init-project，或让 AI 调用 workscene init；
  2. 一域一场景：把领域知识收进 reference/ 的对应分类，而不是塞进 AGENTS.md；
  3. 结论落盘时分类：架构决策写 architecture/，排障写 bugfixed/，调研写 research/；
  4. 跨会话复用：重开任务时先 workscene find <关键词> 命中历史结论，避免重复探索（也省 token，见省 token 与上下文管理）；
  5. 项目专属结论进场景记忆：workscene memory add，与全局偏好分开；
  6. 不再适用的场景：workscene archive 归档，保持当前场景聚焦。
