首页 / 核心能力 / 隔离执行与 worktree

并行改代码最怕互相踩脚：一个任务在改 A 分支，另一个任务在同一工作区改了相同的文件。git worktree 让每个任务在独立目录、独立分支上工作，互不干扰；做完再安全地合回主工作区。定制版把「创建 → 干活 → 合并 → 清理」这套「参考实现」的标准流程封装成 git_worktree 工具。

一、为什么用 worktree

不用隔离 用 worktree
并行任务共享同一工作区，改动互相覆盖 每个任务独立目录 + 独立分支
中途切分支要 stash/commit，打断当前工作 主工作区不动，随时切到别的树干活
合并前难以预演，容易带脏改动进主干 合并走 rebase + 预检 + fast-forward，冲突自动中止

同时它也是隔离执行的载体：全量构建/测试可以挂在某个 worktree 的 workdir 上后台跑，不影响你当前正在编辑的主工作区（见后台任务与通知）。

二、标准流程（四步）

① create  为分支创建工作树（主工作区不动）
② work    在该树目录里干活：改代码 / 构建 / 测试（可配合后台任务的 workdir）
③ merge   把该分支 rebase 到目标分支，再让主工作区 fast-forward
④ remove  合并后移除工作树（可选在 merge 时 cleanup 一步到位）

三、命令表

git_worktree 是自定义工具，在会话中让 AI 调用：

操作 关键参数 说明
create branch [new_branch] [path] 创建工作树；new_branch=true 用 -b 新建分支，否则检出已有分支
list — git worktree list
merge branch [base] [cleanup] rebase 到 base 并 fast-forward 主工作区；cleanup=true 合并后清理
remove path [force] 移除工作树；默认带守护检查，force=true 强制
  • 默认路径：不传 path 时生成到 <项目>/.worktrees/<分支名净化后>/（分支名里的 /、\ 与非法字符会被替换/剔除）；
  • 默认 base：merge 不传 base 时，取主工作区当前分支。

四、merge 的安全语义

merge 不是简单 git merge，而是一套先 rebase、再预检、后快进的保护序列：

步骤 行为 失败时
定位工作树 按 branch 找到对应 worktree 路径 找不到则报错（提示先 create）
脏检查 工作树有未提交改动则拒绝 报错，要求先 commit/stash
rebase 在工作树内 git rebase <base> 自动 git rebase --abort，主工作区与工作树均不受影响
预检 校验 base 是 branch 的祖先（即 branch 已领先） 报错 not ahead of base; cannot fast-forward merge
fast-forward 在主工作区 git merge --ff-only <branch> 仅在预检通过后执行，保证主工作区线性前进
清理（可选） cleanup=true 时移除工作树并 git branch -d 分支未合并时 -d 会拒绝删除

要点：

  • 冲突在 rebase 阶段就中止，主工作区全程不被触碰——不会留下半合并的烂摊子；
  • 只有预检确认「主工作区可以纯快进」时才动主工作区，避免产生意外的 merge commit；
  • base 与 branch 相同会直接报错（无可合并）。

五、remove 的守护

默认（非 force）移除前会做两道检查，任一不满足就拒绝：

守护 条件 提示
脏工作树 工作树有未提交改动 先 commit/stash，或 force=true 丢弃
分支未合并 该分支尚未并入主工作区当前分支 先 merge，或 force=true 强制移除

豁免与边界：

  • 工作树路径不存在时不拦截，交由 git 自行报错；
  • detached 工作树（无对应分支）跳过「未合并」检查；
  • 主工作区无分支或与目标分支同名时，跳过合并检查；
  • force=true 走 git worktree remove --force，不做上述守护。

六、典型并行场景

场景 做法
一边改主干、一边跑全量测试 create 一个测试分支树 → 后台任务 workdir 指向该树跑测试
同时推进两个独立特性 各 create 一个分支树，两棵树并行干活，最后各自 merge
审查 PR 而不打断手头工作 create 检出目标分支到独立树，审阅/复现后再 remove
隔离实验性改动 独立树里试，失败直接 remove --force，主工作区零痕迹

七、一个完整示例

主工作区在 dev，要在独立树里做「重构认证模块」并合回：

① create  git_worktree create branch="refactor-auth" new_branch=true
          → 分支 refactor-auth (new)，路径 .worktrees/refactor-auth/

② work    在该目录改代码；全量测试用后台任务并把 workdir 指向该树：
          background_task start command="bun test" workdir=".worktrees/refactor-auth"

③ merge   确认主工作区在 dev（默认 base），提交干净后：
          git_worktree merge branch="refactor-auth"
          内部：rebase dev → 预检 dev 是 refactor-auth 的祖先
                → 主工作区 git merge --ff-only refactor-auth
          （若 rebase 冲突：自动 abort，进该树解冲突后重试）

④ remove  合并时带 cleanup=true 已自动移除工作树并 git branch -d refactor-auth；
          或事后 git_worktree remove path=".worktrees/refactor-auth"

关键点：步骤 ③ 全程不碰主工作区，直到预检通过才快进——冲突只会发生在工作树内，主工作区始终干净。

八、注意事项

  1. 合并前先提交：工作树必须干净，否则 merge 会被脏检查拒绝；
  2. 冲突在树内解决：rebase 失败会中止，进入该树目录手工解冲突后重试 merge；
  3. 依赖需各自准备：每个树是独立目录，node_modules 等依赖要单独安装（或共享缓存）；
  4. 主工作区分支决定默认目标：merge 前确认主工作区在正确的目标分支上，或显式传 base；
  5. 清理分支要谨慎：cleanup 用 git branch -d（要求已合并），未合并的分支不会被删；
  6. 强制移除会丢改动：remove force=true 前确认工作树里没有还想保留的内容。
