首页 / 核心能力 / 模型配置

模型配置决定「用哪档模型干哪类活」。核心是两条：主力模型干重活、小模型干轻活，以及根据任务把工作放进正确的模型——这是省 token 与省成本最有效的杠杆（见省 token 与上下文管理）。

一、主力模型与小模型

字段 作用 写法
model 默认主模型 <provider>/<model>，如 openai/gpt-5.4
small_model 小模型（标题生成、压缩等轻量任务；子代理可复用） <provider>/<model>，如 deepseek/deepseek-chat
vision_model 视觉模型（可选；auto/vision 档位的解析目标） <provider>/<model>

这些字段都在 ~/.config/opencode/opencode.json 中配置：

{
  "model": "openai/gpt-5.4",
  "small_model": "deepseek/deepseek-chat",
  "vision_model": "openai/gpt-5.4" // 可选：供 auto/vision 档位使用
}

二、模型档位别名（small 与 auto/*）

agent frontmatter、opencode.json 顶层 model、启动参数 -m 都支持档位别名——用虚拟档位表达「哪档模型干哪类活」：

别名 解析为 回退行为
small / auto/flash 小模型（small_model） 解析不到时回退主力模型（子代理配置里则回退父会话模型）
auto / auto/pro 主力模型（model） ——
auto/vision 视觉模型（vision_model） 未配置或解析失败时回退主力模型

small / auto/flash 的小模型解析顺序：

  1. 取 opencode.json 的 small_model（若配置）；
  2. 否则按 provider 推断小模型（优先 gemini-flash / gpt-nano / claude-haiku 家族）；
  3. 都解析不到时回退主力模型（子代理配置中则不设置 model，回退父会话模型）。

子代理 frontmatter 用法示例：

---
mode: subagent
model: auto/flash
description: 只读代码探索代理
permission:
  "*": deny
  read: allow
  glob: allow
  grep: allow
---

未识别的档位（如 auto/xxx）按普通模型名处理，走标准「模型不存在」报错——不会静默选错模型。

.opencode/agent/explorer.md 已默认挂载 model: small：探索、扫描这类轻任务走小模型档，重活仍由主代理/executor 用主力模型。这就是「把工作放进正确的模型」。

三、Provider 配置写法

opencode.json 的 provider 字段：每个 provider = npm SDK 包 + options（baseURL/apiKey）+ models 清单。apiKey 一律用 {env:XXX} 引用环境变量，仓库不出现任何真实密钥：

{
  "provider": {
    "openai": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "OpenAI",
      "options": {
        "baseURL": "{env:OPENAI_BASE_URL:https://api.openai.com/v1}",
        "apiKey": "{env:OPENAI_API_KEY}"
      },
      "models": {
        "gpt-5.4": { "name": "GPT 5.4" }
      }
    },
    "anthropic": {
      "npm": "@ai-sdk/anthropic",
      "name": "Anthropic",
      "options": { "apiKey": "{env:ANTHROPIC_API_KEY}" },
      "models": {
        "claude-sonnet-4-6": { "name": "Claude Sonnet 4.6" }
      }
    }
  },
  "model": "openai/gpt-5.4",
  "small_model": "deepseek/deepseek-chat"
}

常用 npm 包：

npm 包 适用 provider
@ai-sdk/openai-compatible OpenAI 兼容网关（openai / deepseek / 企业网关等）
@ai-sdk/anthropic Claude
@ai-sdk/google Gemini
@ai-sdk/openai / @ai-sdk/azure / @ai-sdk/xai / @ai-sdk/mistral / @ai-sdk/alibaba 各官方 SDK

企业 / 私有 provider（脱敏示例）

内网地址、凭据一律不进 git，示例用占位符：

{
  "provider": {
    "enterprise": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "企业网关",
      "options": {
        "baseURL": "{env:ENTERPRISE_BASE_URL:https://gateway.example.com/v1}",
        "apiKey": "{env:ENTERPRISE_API_KEY}"
      },
      "models": {
        "gpt-5.4": { "name": "GPT 5.4" }
      }
    }
  }
}

opencode.json 是唯一持久配置（非 git），私有 provider 与公开 provider 并存；init.sh --force 重建时会自动保留 model / small_model / 私有 provider。

四、切换模型

方式 操作
TUI 模型选择器 Ctrl+X m（<leader>m），F2 / Shift+F2 循环最近模型
启动时指定 opencode -m <provider>/<model>（也支持档位别名，如 -m auto/flash）
会话内切换 TUI 模型选择器面板（model_picker / model_tabs 在 tui.json 配置）
永久默认 改 opencode.json 的 model / small_model / vision_model 字段

五、模型列表与发现机制

模型元数据来自模型目录服务，缓存到本机并按需刷新：

方式 说明
CLI opencode models [provider] [--verbose] [--refresh] 列出可用模型
缓存文件 ~/.cache/opencode/models.json（模型清单缓存，离线编译也用它）
覆盖源 环境变量 OPENCODE_MODELS_URL 可改目录源；OPENCODE_MODELS_PATH 指定缓存路径
禁用拉取 OPENCODE_DISABLE_MODELS_FETCH 关闭联网刷新

机制要点：

  • 缓存有 5 分钟 TTL；进程启动时后台按 60 分钟周期刷新（跨进程用文件锁避免竞争）；
  • opencode models --refresh 强制刷新；
  • 目录提供每个模型的 limit（context / output）、cost、family 等元数据——small 别名推断、自动压缩预算都依赖这些元数据。

六、私有模型的 limit 与自动压缩

opencode 的自动压缩触发条件是「估算 tokens > limit.context − max(limit.output, buffer)」。模型缺 limit 就永远不触发压缩。

  • 官方模型：由目录自动解析 limit，无需配置；
  • 私有模型：./init.sh 会为缺 limit.context 的私有模型自动注入 context=200000 / output=32768（只填缺失值，不覆盖已有配置）。

七、落地清单

  1. 配好两档：model 用主力，small_model 用轻量档（有视觉任务再加 vision_model）；
  2. 轻活走档位别名：探索/摘要/标题写 model: small（或 auto/flash），explorer 已内置；
  3. 重活再上主力：需要推理/长链路的任务用主代理与 executor；
  4. provider 写脱敏值：baseURL 用占位符、apiKey 用 {env:XXX}，密钥进 secrets.env（见凭据与权限）；
  5. 模型过旧就刷新：opencode models --refresh；
  6. 成本可度量：评估里加 cost_under / latency_under 门禁，见评估系统。
