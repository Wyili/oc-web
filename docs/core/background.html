首页 / 核心能力 / 后台任务与通知

构建、全量测试、长跑服务这类命令动辄数分钟、输出上千行。把它们放到后台，既不让主对话卡住，也不让大段输出污染上下文——完成后只回收「退出码 + 结果摘要」，需要细节时再按需取日志。

一、什么时候该后台跑

场景 建议
全量构建 / 全量测试 后台跑，完成通知后再取结果
开发服务器 / 长时间监控 后台跑，需要时 output 看日志
可能产生大量输出的命令 后台跑（输出落盘，不占对话）
秒级即可返回的命令 前台直接跑（后台反而多一层）
需要中途交互的命令 不要放后台（后台无 stdin）

二、background_task 工具

让 AI 调用 background_task 管理后台命令：

操作 参数 说明
start command [workdir] 后台启动命令，返回任务 ID；输出写入 .opencode/tasks/<id>.log
list — 列出所有后台任务及状态（running / completed / stopped）
output task_id 读取某任务的输出（超过 50KB 截断，保留末尾 50KB）
stop task_id 终止运行中的任务（向进程组发 SIGTERM）

start 会用 sh -c 以 detached 方式启动子进程，stdout/stderr 同时管道到日志文件，然后 unref()——父进程（对话）可继续，命令照跑。

提示：workdir 可指定命令的工作目录，例如跑在某个 git worktree 里（见隔离执行与 worktree）。

三、任务记录与退出码

每个任务在 .opencode/tasks/<id>.json 落一条记录：

字段 说明
id / command / workdir / pid 标识、命令、工作目录、进程号
status running / completed / stopped
started_at 启动时间
exit_code 完成时写入的退出码（null 表示信号终止等）
finished_at 完成时写入的时间戳

完成时还会：

  • 向日志文件追加完成标记 --- task completed at <时间> (exit <code>) ---；
  • 先落完成标记、再写 status=completed，保证「状态可见时标记已存在」的顺序一致。

PID 对账：list 时会核对每个 running 任务的进程是否还活着，进程已死则自动修正为 completed——避免任务实际结束却一直显示运行中。

四、完成通知

后台任务完成时，best-effort 发一条桌面通知：

标题: 后台任务完成
正文: <id> exit=<code> · <命令前 60 字符>
  • 通过 notify-send 发送，从不抛异常：命令不存在或无图形会话时静默降级；
  • 设 MA_NO_DESKTOP_NOTIFY=1 可关闭桌面通知（如无桌面环境或不想被打扰）；
  • 需要跨设备提醒时，也可用 feishu_notify 主动推送结果。

五、定时提醒（cron）

cron 工具用于登记定时提醒（注意：opencode 不能真正调度，它把提醒记录下来，在后续会话中作为上下文浮现）：

操作 参数 说明
create cron prompt [recurring] 登记任务（默认 recurring=true），存 .opencode/cron/jobs.json
list — 列出已登记任务
delete id 删除任务
  • cron 支持标准 5 段 cron 表达式（如 "0 9 * * 1" = 每周一 09:00）或 Go 风格时长（"30m"、"2h"）；
  • TUI 里也可用 /loop <cron> <内容> 快速创建。

六、生命周期 hooks：审计与通知

global/lifecycle-hooks.ts 在每次工具调用前后运行，自动完成：

行为 落点
工具调用审计 追加 JSONL 到 ~/.config/opencode/audit.log（before/post 两阶段，附工具名与标题）
任务步骤结束通知 步骤完成/失败发桌面通知（Agent step completed / Agent step failed）
技能使用统计 skill 工具加载时记录 skill-usage.json
工具使用统计 记录调用次数与失败次数（失败按 callID 反查补记）
权限询问审计 记录每次授权询问
压缩时注入 压缩上下文时注入会话记忆种子与「活跃任务」工作锚点

审计失败不阻塞执行——统计与审计都是旁路记录。

七、失败排查

现象 排查
任务一直 running 命令可能确实在跑；output 看日志是否卡住；必要时 stop
任务显示 completed 但没有输出 输出在 .opencode/tasks/<id>.log；output 截断按末尾 50KB，关键信息应看日志文件
没收到桌面通知 无图形会话或 notify-send 缺失时静默；检查 MA_NO_DESKTOP_NOTIFY 是否为 1
退出码非 0 output 读日志尾部定位报错；结合快速定位问题做二分/最小复现
stop 后仍占端口 stop 向进程组发 SIGTERM；若子进程另起进程组，需手工清理
命令要交互 后台无 stdin，改用前台执行

八、一个端到端示例

① 启动    background_task start command="bun run build" 
          → ID task_xxx，日志 .opencode/tasks/task_xxx.log

② 干别的  主对话继续处理其他任务（后台命令不受影响）

③ 查状态  background_task list
          → 完成时显示 COMPLETED + exit: 0；未完成显示 RUNNING

④ 取结果  background_task output task_id="task_xxx"
          → 返回状态行 + 命令 + 日志（超 50KB 只保留末尾 50KB）

⑤ 完成通知 桌面弹出「后台任务完成 task_xxx exit=0 · bun run build」
          （设 MA_NO_DESKTOP_NOTIFY=1 关闭）

如果 ④ 里 exit 非 0 或日志尾部有报错，就按快速定位问题的思路定位——注意区分「日志有内容」与「命令成功」，以退出码为准。

九、落地清单

  1. 长命令一律后台：构建 / 全量测试 / 服务；
  2. 大输出交给日志：完成后再 output 看尾部，避免整段读进上下文；
  3. 靠退出码判断成败：记录里有 exit_code 与 finished_at，不要只凭日志有无内容猜；
  4. 要提醒就配通知：默认桌面通知，无桌面环境用 MA_NO_DESKTOP_NOTIFY=1 关闭或改用飞书；
  5. 定时提醒用 cron：登记的提醒会在后续会话中作为上下文浮现；
  6. 跑在隔离目录：结合 workdir 指向 worktree，长命令不影响主工作区。
