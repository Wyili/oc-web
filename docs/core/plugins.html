首页 / 核心能力 / 插件与扩展

插件是 opencode 的会话内扩展机制：用 TypeScript 挂接生命周期钩子，或把技能 + 命令 + 子代理打包成一个可分发单元。定制版用插件实现审计日志、使用统计、活跃任务注入、编辑后自动检查与桌面通知等横向能力。

一、插件形态

定制版有三类插件落点：

形态 位置 加载方式 典型
TS 钩子文件 .opencode/global/*.ts init.sh 以文件级 symlink 到 ~/.config/opencode/plugin/，自动加载 lifecycle-hooks.ts
目录形态插件 .opencode/plugins/<name>/ 随 skills.paths 扫描，内含 skills/ + commands/ + subAgents/ jira / gerrit / kb（企业插件）
TUI 插件 .opencode/global/*.ts + tui.json 声明 文件放 global/，但 TUI 只认 tui.json 的 plugin 字段（不做目录扫描） asset-manager-tui.ts

单文件钩子插件是 symlink，改仓库文件即实时生效；目录形态插件随目录被发现；TUI 插件必须同时改 tui.json，否则不会加载。

二、插件如何被发现

  • 全局钩子：global/*.ts 经 init.sh 同步为 ~/.config/opencode/plugin/<name>.ts，opencode 启动时自动加载；
  • 插件目录：<项目>/.opencode/plugins/ 与全局插件目录由 skills.paths 覆盖扫描；
  • TUI 插件声明（tui.json）：
{
  "plugin": [
    "./global/asset-manager-tui.ts",
    ["./plugins/tui-smoke.tsx", { "enabled": false }]
  ]
}
  • /plugins 命令可列出当前加载的插件、技能、工具与命令；/reload 刷新。

三、生命周期事件

lifecycle-hooks.ts 挂接了以下钩子（对应 opencode 插件事件）：

钩子 对应事件 触发时机
tool.execute.before PreToolUse 每次工具调用前
tool.execute.after PostToolUse 每次工具调用后（含阻塞式日志）
event Notification / 审计 会话步骤结束/失败、工具失败、权限请求
experimental.session.compacting session_memory_extraction 上下文压缩时

四、钩子能力一览

能力 实现方式 落点
审计日志 每次工具调用追加一行 JSONL ~/.config/opencode/audit.log
技能使用统计 skill 工具加载时 count+1 ~/.config/opencode/skill-usage.json
工具使用统计 每次工具调用计数，失败按 callID 反查补记 ~/.config/opencode/tool-usage.json
权限审计 监听 permission.asked 事件记录授权决策 audit.log
活跃任务注入 压缩时读项目 tasks.json，把 in_progress 任务作为工作锚点注入 会话上下文
会话记忆种子 压缩时抽取关键信息注入 ~/.config/opencode/session-memory.md
自定义检查器 编辑类工具执行后按文件模式跑检查命令，结果追加到工具输出 custom-checkers.json
桌面通知 步骤完成/失败时 notify-send 系统通知

4.1 自定义检查器

对齐 LSP custom_checkers：编辑 .py 等文件后自动运行检查命令，结果对模型可见。

// 项目 .opencode/custom-checkers.json 或全局 ~/.config/opencode/custom-checkers.json
[
  { "name": "pyright", "patterns": ["**/*.py"],
    "command": "pyright --outputjson ${FILE}", "timeout": 30 }
]
  • 触发工具：edit / write / apply_patch；
  • ${FILE} 占位符替换为被编辑文件的绝对路径；
  • 项目级配置优先于全局配置。

4.2 通知的双通道

  • TUI 内提醒：由 tui.json 的 attention 配置原生提供（通知栏 + 可选声音），无需插件代码；
  • 桌面通知：由 lifecycle-hooks 用 notify-send 发送，无桌面环境时静默降级。

五、TUI 插件：asset-manager-tui

asset-manager-tui.ts 注册 TUI 侧 /asset_manager 斜杠命令，打开交互式资产列表（✅ 已拉取 / ⬜ 未拉取），选择未拉取的资产直接拉取：

  • 纯前端直通：列表来自本地缓存 git 仓库 + meta.json，拉取是纯 git/文件操作，全程零 LLM；
  • 声明式加载：必须在 tui.json 的 plugin 字段注册，TUI 不做目录扫描；
  • 与对话内 asset_manager 工具互为两种入口（见 自定义工具）。

六、插件的分发：@plugin 与资产化的区别

包成 @plugin 的目录既能随仓库内置，也能在远程资产仓库分发：

@plugin（会话内扩展） @tool（独立程序） 内置能力
本质 skill + 斜杠命令 + 子代理的打包 独立可执行程序 编译进二进制的核心能力
生命周期 依赖 opencode 会话加载 独立进程，与会话解耦 随会话
分发 asset pull + asset setup（部署到项目） asset pull + asset run 无需分发
  • 资产化分发：远程资产仓库（github.com/Wyili/opencode-assets，地址在 .opencode/opencode.jsonc 的 assets.repo）；asset pull 拉缓存、asset setup 部署、asset push 发布；
  • 内置 vs 分发边界：基础核心能力（子代理、workscene、goal/debug/evaluate 等自研技能）内置保留；功能类资产（docx/pdf/pptx/xlsx、jira/gerrit/kb 等）内置提交于 .opencode/skills/ 与 .opencode/plugins/，同时保留在远程仓库可分发；
  • 两者的区别在形态而非来源：决定放哪个目录，看它是「会话内扩展」还是「独立程序」。

七、落地清单

  1. 横向能力用钩子——审计、统计、通知这类「每次都要做」的事，挂 global/*.ts，别写进提示词；
  2. TUI 插件记得改 tui.json——文件放对位置还不够，必须声明；
  3. 检查器按需开——custom-checkers.json 控制编辑后自动检查的范围与超时；
  4. 插件也过隐私扫描——打包分发前用 privacy 自检；
  5. 优先包成资产——可复用的插件组合走 @plugin 分发，而非各处手工维护。

技能本身见 技能系统；资产操作见 自定义工具 与仓库 .opencode/README.md。
