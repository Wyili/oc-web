首页 / 快速上手 / 项目上下文与记忆

模型每轮都能"看见"的东西，决定了它是否懂这个项目。opencode 定制版把这类知识分三层：项目上下文（怎么做事）、自动记忆（用户与项目历史）、工作场景（领域知识库）。三层各管一段，越精炼越省 token。

一、三层记忆的分工

层 载体 回答什么 生效范围
项目上下文 AGENTS.md "这个项目怎么做事"（规范、命令、红线） 每次会话自动加载
自动记忆 MEMORY.md + memory/*.md "用户习惯与项目历史"（偏好、决策、解法） 全局，跨项目
工作场景 workscenes/<场景>/reference/ "某个领域的既有知识"（架构、调研、bug、需求） 项目内，按场景切换

一句话：init-project 搭骨架 → 代理选"谁做"、上下文定义"怎么做"、场景提供"做什么"的领域知识。

二、AGENTS.md 的查找与合并顺序

opencode 会在会话开始时收集一组指令文件，拼进系统提示词。查找顺序如下：

  1. 全局指令文件（取第一个存在的）： - ~/.config/opencode/AGENTS.md - ~/.claude/CLAUDE.md（可被开关关闭）
  2. 项目级指令文件（从当前目录向项目根查找，只取第一个命中的层级，避免把每一级祖先都堆进来）： - AGENTS.md → CLAUDE.md → CONTEXT.md（CONTEXT.md 已标记为 deprecated，仅为兼容保留）
  3. instructions 配置：opencode.json 的 instructions 数组里列出的文件与 URL 都会追加。

本项目由 init.sh 写入：

{
  "instructions": [
    "<仓库>/.opencode/AGENTS.md",          // 本仓库（项目级）行为规范
    "<仓库>/.opencode/global/AGENTS.md"    // 全局行为规范
  ]
}

合并结果 = 全局指令 → 项目指令 → instructions 各项（按列出顺序），每段以 Instructions from: <路径> 开头依次注入。二者不冲突时叠加生效；冲突时后出现的更具体、优先级更高。

环境变量 OPENCODE_DISABLE_PROJECT_CONFIG 可关闭项目级发现，只保留全局指令。

三、SYSTEM.md 与 APPEND_SYSTEM.md

这两个文件名来自内部「参考实现」的系统提示词分层约定，定制版已原生支持：

文件 作用 生效范围
SYSTEM.md 整体替换默认系统提示词 仅对没有自定义提示词的代理（主代理，如 build/plan）生效；explorer/evaluator 等有自己提示词的代理不受影响
APPEND_SYSTEM.md 追加到系统提示词末尾（全局行为约定） 所有代理可见，位于系统提示词最后一段

查找顺序（单文件、先找到的生效）：

<cwd>/<文件名>  →  <cwd>/.opencode/<文件名>  →  ~/.config/opencode/<文件名>
  • .opencode/ 下已有同名文件：APPEND_SYSTEM.md 记录全局行为约定（已生效）；SYSTEM.md 当前为「未启用覆盖」说明，写入内容即启用替换。
  • 注意：SYSTEM.md 整体替换会丢失默认提示词中的内置能力，慎用；只想补充规则时优先用 APPEND_SYSTEM.md 或 AGENTS.md。

四、记忆系统（MEMORY.md）

自动记忆用于沉淀跨会话的稳定知识：

  • 位置：~/.config/opencode/MEMORY.md（索引，上限 200 行）+ ~/.config/opencode/memory/<topic>.md（主题文件）；
  • 会话开始自动读取，结束前刷新；对话中也可让 AI 调用 memory 工具。
操作 说明
memory list 读取 MEMORY.md 索引
memory add <标题> [--content <正文>] 追加一条（自动建 topic 文件并链接）
memory refresh <slug> 读取某主题文件内容
memory activate <slug> 标记激活（加 ★ 前缀）

该存什么：稳定模式、架构决策、用户偏好、重复出现的解决方案。 不该存什么：会话状态、未验证的信息、会话噪声。

五、与工作场景的关系

工作场景 = 领域知识库域。每个场景是一个目录：

.opencode/workscenes/<场景>/
├── scene.md                 # 场景定义（frontmatter：name/description/reminders）
├── memory/MEMORY.md         # 场景记忆
└── reference/               # 参考知识：research / architecture / bugfixed / requirements
操作（workscene 工具） 命令
初始化默认场景 workscene init
创建场景 workscene create <name> --description "用途"
切换当前场景 workscene activate <name>
列出场景 + 文件树 workscene status
搜索参考知识 workscene find <关键词> [--category architecture/research/bugfixed/requirements]
场景记忆 workscene memory add <内容> / workscene memory list

场景与 MEMORY.md 的区别：MEMORY.md 记用户画像与项目历史（跨项目、全局），场景 reference/ 记领域知识（项目内、按场景隔离）。切换场景 = 切换 AI 可检索的知识库与记忆域。scene.md 的 reminders 字段可注入提醒。

参考知识建议按类型用固定结构书写：

  • 架构：Summary → Structure → Key Findings
  • Bug 修复：Summary → Symptoms → Root Cause → Fix
  • 调研：Summary → Conclusion → Analysis

详细操作见 工作场景。

六、写好 AGENTS.md 的原则

AGENTS.md 是每轮固定成本——文件越臃肿，每轮都贵。原则只有一条：只写 Agent 无法从代码推断的知识与约束。

  • ✅ 该写：项目定位、构建/测试/类型检查命令、非直观的约定、隐私红线、必须遵守的流程；
  • ❌ 别写：能从代码/配置读出的内容、大段背景科普、一次性的临时事项；
  • ✅ 具体可执行：写"测试命令：bun test"，而不是"测试要充分"；
  • ✅ 分层放置：全局行为放 .opencode/global/AGENTS.md，项目专属放 .opencode/AGENTS.md；
  • ✅ 动态知识不进 AGENTS.md：会变化的事实放记忆/场景 reference，用工具按需检索；
  • ✅ 改完即刷新：会话中途频繁改 AGENTS.md 会打断提示词缓存（Context Epoch），尽量稳定。
