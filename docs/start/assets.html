首页 / 快速上手 / 资产与常用命令

定制版把可复用能力（子代理、工具、技能、插件、启动器）打包成资产，像包管理器一样 list / pull / run / setup / export。资产不进主仓库——它们统一放在独立资产仓库，按需拉取。本文给出两类入口、操作速查与本地开发（mirror）。

一、五类资产

类型 引用格式 典型内容
子代理 @agent/xxx AGENTS.md + skills/ + workflows/
工具 @tool/xxx 独立可执行程序（entry，可 run）
技能 @skill/xxx SKILL.md（加载步骤指令）
启动器 @launcher/xxx launch.py（可执行）
插件 @plugin/xxx skillsDir + commandsDir + subAgentsDir

每个资产 = meta.json（name / type / version / description / requires / compatibility）+ 内容文件 + 自述文档（skill 写 SKILL.md、tool/plugin 写 README.md、agent 写 AGENTS.md），随资产一起分发。查详情用 asset info @type/name。

二、两条入口

asset_manager 不是 shell 命令，有两类入口：

  • TUI 插件命令（推荐，不经 LLM）：输入 / 选择 /asset_manager 回车 → 交互式列表（✅ 已拉取 / ⬜ 未拉取），选中 ⬜ 直接下载。
  • AI 工具 / CLI（经 LLM 或 bun）：对话中让 AI 调用 asset_manager 工具；命令行用 asset（init.sh 生成的 wrapper，直接 exec bun 到工具，不经过 LLM）。

三、操作速查

asset <操作> @type/name（对话中即 asset_manager 工具的同名操作）：

操作 作用 示例
list 列出可用资产，可按类型过滤、只看本地 asset list @skill --local
search 按名称/描述/标签模糊匹配（本地 + 远程） asset search docx
info 查看资产详情（元信息 + 文件列表） asset info @tool/oc-lark
pull 拉取到全局缓存 ~/.config/opencode/assets/ asset pull @skill/docx
install 拷贝到当前项目 .opencode/assets/（项目级，可改后 push） asset install @tool/xxx
run 运行 tool / launcher（执行 entry / launch.py） asset run @launcher/oc-default
setup 部署 skill/plugin 到项目 .opencode/skills|plugins/（目录扫描即生效） asset setup @skill/docx
export 导出资产到指定目录 asset export @skill/docx --output /tmp/dist
push 发布到远程仓库（meta 校验 + 隐私扫描 + 身份检查 + 提交推送） asset push @skill/demo
status 查看本地资产 vs 发布工作区差异 asset status

补充：

  • pull @launcher/xxx 会读 meta.json 的 requires 字段，自动拉取依赖组件（如 launcher 依赖的 tool）；
  • setup 只支持 skill 与 plugin：skill → .opencode/skills/，plugin → .opencode/plugins/，部署后目录扫描即生效；
  • asset new @type/name 创建模板（走 new-asset 工具，5 类都支持）；asset identity "<昵称>" "<noreply 邮箱>" 注册发布身份。

四、资产来源与查找优先级

asset-manager 解析资产时按下列顺序查找，先命中先用：

  1. --mirror 指定的本地镜像目录（开发测试用，跳过 git 拉取）；
  2. 全局缓存 ~/.config/opencode/assets/<类型>/<名称>/（pull 落盘处）；
  3. 远程资产仓库（assets.repo 配置的仓库）。

项目级 <项目>/.opencode/assets/<类型>/<名称>/ 是 install / new-asset 的落盘位置，用于项目内定制与发布；文档约定的覆盖优先级为 项目级 > 全局 > 远程。

资产仓库地址解析优先级：项目 .opencode/opencode.jsonc 的 assets.repo → 环境变量 OPENCODE_ASSETS_REPO（兜底）。换源只需改一处：

// .opencode/opencode.jsonc
{
  "assets": { "repo": "https://github.com/<owner>/<assets-repo>" }
}

五、mirror：本地开发

开发/测试资产时，用 --mirror <目录> 指定本地目录作为资产源，跳过 git 拉取。目录结构须与远程仓库一致：

<mirror>/
├── agents/<name>/
├── tools/<name>/
├── skills/<name>/
├── launchers/<name>/
└── plugins/<name>/

asset list @skill --mirror /path/to/mirror        # 从镜像列出
asset pull @skill/xxx --mirror /path/to/mirror    # 从镜像拉取（显示来源）
asset info @tool/xxx --mirror /path/to/mirror     # 查看详情
asset run  @tool/xxx --mirror /path/to/mirror     # 直接运行

设置 mirror 后，list / pull / info / export / run / setup 都优先从镜像读取——离线也能开发调试。

六、本地修改与删除

拉到本地后资产就是普通文件，可直接编辑。三层位置：

位置 用途
<项目>/.opencode/assets/<类型>/<名称>/ 项目级覆盖（install 落盘）
~/.config/opencode/assets/<类型>/<名称>/ 全局缓存（pull 落盘）
远程仓库（assets.repo） 只读源

删除分三层，通常只需做前两步：

# ① 移除项目内部署（skill → .opencode/skills/，plugin → .opencode/plugins/）
rm -rf .opencode/skills/docx
rm -rf .opencode/plugins/jira

# ② 清除全局缓存（本地 list --local 即不再显示）
rm -rf ~/.config/opencode/assets/skills/docx

# ③ 从远程彻底删除：在资产仓库删除对应目录并推送（仅维护者）
  • 只做 ①：功能立即卸载，缓存保留可再部署；
  • ①② 都做：需重新 pull 才能再用；
  • ③ 影响所有使用者。

七、创建与发布

asset new @skill/demo                      # 创建模板（.opencode/assets/skills/demo/）
# 编辑完善 SKILL.md / meta.json 后：
asset push @skill/demo                     # 发布到远程资产仓库
asset export @skill/demo --output /tmp/dist   # 或仅导出为目录

asset push / asset status 委托 .opencode/scripts/publish-assets.sh（init.sh 同步为 bin/publish-assets）：负责 meta schema 校验 + 隐私扫描 + git 身份检查 + 提交推送；未配置发布身份或含敏感信息时会明确报错。资产内容不得包含业务名、公司名、内网域名、真实密钥或人名。

八、@tool 还是 @plugin

决定新资产放哪类目录：

@tool @plugin
本质 独立可执行程序（entry + 可 run） 会话内扩展（skillsDir + commandsDir + subAgentsDir）
典型 飞书桥接器、mcp-inspector、system-info jira / gerrit / kb（skill + 斜杠命令挂到会话）
生命周期 独立进程，与会话解耦 依赖 opencode 会话加载
asset 操作 pull / run（不 setup） pull / setup（部署 skill/command 到项目）

@tool 是独立服务（自己拉起服务、对话发生在别处）；@plugin 是挂在 opencode 会话里的 skill + 命令集合。
