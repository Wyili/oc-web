首页 / 快速上手 / 安装与配置

顺序：先安装代码，再初始化。新机器 ① 拉代码 curl -fsSL https://raw.githubusercontent.com/Wyili/opencode/dev/bootstrap.sh | bash → ② 初始化 + 编译 ./init.sh --build → ③ source ~/.bashrc；已有仓库直接 cd ~/opencode && ./init.sh。

opencode 定制版 = 本仓库源码编译。二进制不进 git（dist/ 被忽略），所以新机器必须本地编译一次（不要装官方版）。init.sh 负责把仓库里的运行时配置层部署为全局配置（~/.config/opencode/）。

一、新机器安装

# ① 拉代码 + 部署全局配置（自动装 bun、生成 opencode.json、同步全局、提示隐私信息）
curl -fsSL https://raw.githubusercontent.com/Wyili/opencode/dev/bootstrap.sh | bash

# ② 初始化 + 编译定制版二进制（含本仓库所有定制功能）
opencode init --build          # 或 cd ~/opencode && ./init.sh --build

# ③ 新终端生效
source ~/.bashrc
  • bootstrap.sh：默认 clone 到 ~/opencode（可用 OPENCODE_INSTALL_DIR 改），随后调用 init.sh；
  • 编译需网络（models.dev 模型清单 + npm 镜像）；离线编译需先缓存 ~/.cache/opencode/models.json；
  • 产物：packages/opencode/dist/opencode-linux-x64/bin/opencode，自动 symlink 到 ~/.local/bin/opencode。

二、三种初始化方式

方式 命令 作用域 何时用
全局初始化 ./init.sh（等价 opencode init） 用户级 ~/.config/opencode/ 新机器/换机后部署公共配置
项目级初始化 opencode init-project [目录] 当前项目 <项目>/.opencode/ 在任意项目创建配置骨架
项目级 .opencode/ init-project 生成后编辑 项目（可提交 git） 项目共享：agent / skills / workscenes

关键区别：

  • 全局（~/.config/opencode/）放本机私有：密钥、私有 provider、记忆（非 git）；
  • 项目（<项目>/.opencode/）放项目共享：子代理、技能、工作场景（可提交 git）；
  • 本仓库自身就是「一个项目」：根目录已有 .opencode/，全局通过 instructions / skills.paths 引用它，无需再跑 init-project。

三、依赖

依赖 缺失时 用途
bun init.sh 自动安装 仓库依赖、provider SDK、自定义工具运行时
python3 警告（不阻断） 插件脚本（jira/gerrit/kb）、私有配置合并
git 需先安装 bootstrap.sh 克隆仓库

四、init.sh 自动完成什么

无需手工干预，init.sh 会：

  • 装依赖：bun 缺失自动安装；python3 缺失仅警告；
  • 生成 opencode.json：不存在时写通用模板（只含公开 provider）；
  • 全局同步：agent/、command/ 以 symlink 指向仓库（改仓库文件即生效）；plugin/*.ts 文件级 symlink；模板首次生成；
  • 建目录骨架：assets/{agents,launchers,plugins,skills,tools}、memory/、~/.cache/opencode，以及 bin/ 下的 CLI wrapper（asset、plan、privacy、skill-usage 等，不经过 LLM）；
  • provider SDK 依赖：首次生成 package.json 并 bun install；
  • 生成敏感词清单空模板 sensitive-patterns.txt；
  • 写 ~/.bashrc：补齐 PATH、密钥加载（set -a; source ~/.config/secrets.env; set +a，放在交互守卫之前）与 opencode init / init-project wrapper；
  • 结束输出环境自检报告。

密钥是按需配置的：初始化不强制输入。用到哪个配哪个（/secrets 命令、编辑 ~/.config/secrets.env，或 ./init.sh --prompt-secrets 交互引导）。

五、覆盖策略

init.sh 默认保护用户数据，只有显式 --force / --reset 才重建：

内容 默认 --force --reset
opencode.json 已存在不覆盖 删除重建 + 保留私有配置（备份 .bak.*） 删除重建 + 恢复纯模板
package.json（provider SDK） 已存在不重生成 删除重建 删除重建
agent/ command/ plugin/*.ts symlink，新增实时生效 同左 同左
MEMORY.md / memory/ 保留 保留 清空（先备份到 /tmp）
sensitive-patterns.txt 首次生成，保留 保留 清空
secrets.env / tui.json / .masterkey 保留 保留 清空（密钥需重配或 --restore）
~/.bashrc 的 PATH / wrapper 已存在不覆盖 不覆盖 不覆盖

init.sh 的常用开关：

开关 作用
--build 顺带编译二进制
--force 重建 opencode.json 与 provider 依赖（自动保留私有配置）
--reset 完全初始化：清空全部非 git 私有内容（先备份到 /tmp）
--backup 打包私有配置到 ~/opencode-config-backup-<ts>.tar.gz（0600，含密钥勿提交）
--restore <备份.tar.gz> 从备份还原（还原前自动备份当前到 /tmp）
--prompt-secrets 交互式配置密钥（默认不交互）

opencode.json 是唯一持久配置（非 git）。--force 重建时会从旧备份自动合并 model / small_model / 模板之外的私有 provider，并给缺 limit 的私有模型注入默认预算（context=200000 / output=32768），保证自动压缩能触发。

六、配置落点

改什么 改哪里
模型 / provider ~/.config/opencode/opencode.json → model / small_model / provider
API keys / 凭据 ~/.config/secrets.env（0600，纯 KEY=value）
快捷键 / 模型选择器 ~/.config/opencode/tui.json
项目级配置 <项目>/.opencode/opencode.jsonc（与全局自动合并）
行为规则（给 AI 看） <项目>/.opencode/AGENTS.md

常用字段（均可写在 opencode.json）：

字段 说明
model / small_model 主模型 / 小模型（标题生成、压缩等轻任务）
permission 工具级权限规则：ask / allow / deny（见 启动与界面）
subagent_max_concurrency 子代理并发上限，默认 4，范围 1-8（防止并发风暴）
subagent_depth 子代理嵌套深度，默认 1（禁止子代理再起子代理）
compaction 上下文压缩策略（auto / tail_turns / preserve_recent_tokens / reserved）
tool_output 工具输出截断（max_lines / max_bytes）

七、环境自检

init.sh 结束时打印自检清单，逐项确认：

  • ✅ opencode 二进制存在（packages/opencode/dist/...），不存在会提示 --build；
  • ✅ ~/.local/bin/opencode symlink 正确；
  • ✅ 全局配置 ~/.config/opencode/opencode.json 存在；
  • ✅ SSH 公钥存在（Gerrit 插件依赖）；
  • ✅ 敏感词清单非空（提交拦截用）；
  • ✅ secrets.env 已配置变量数（0 则提示"暂不可用"）。

随时可手动体检：

opencode debug config                 # 确认所用 provider 的 apiKey 非空
opencode run "回复ok" --model openai/gpt-5.4   # 实际调用验证（报 401 见下）

八、移植检查清单（换机/迁移后必做）

密钥与私有 provider 不进 git，迁移后需手动补齐，否则报 401「未提供认证凭据」：

# 检查项 命令
1 配置密钥 新建 ~/.config/secrets.env（纯 KEY=value，不要 export 前缀），chmod 600
2 私有 provider 从旧机拷贝整个 ~/.config/opencode/opencode.json
3 环境变量生效 source ~/.bashrc（新终端自动生效）
4 验证 apiKey opencode debug config → 所用 provider 的 apiKey 非空
5 验证实际调用 opencode run "回复ok" --model <provider>/<model> → 有内容即成功

快速自检：set -a; source ~/.config/secrets.env; set +a && env | grep -c '^OPENAI_API_KEY=' 输出 1 即就绪。

九、日常更新

场景 命令
更新定制版（拉代码 + 重编译） cd ~/opencode && git pull && opencode init --build
只更新配置不重编译 cd ~/opencode && git pull && opencode init
改配置/AGENTS.md/skills 不用编译，./init.sh 即可；运行中 /reload 刷新

十、常见坑

现象 原因 解决
opencode: command not found 新终端未加载 PATH 重启终端，或 source ~/.bashrc
命令还是旧版本 git pull 后没重编译 ./init.sh --build
模型/插件 401「未提供认证凭据」 密钥未配置或未 source 见上文「移植检查清单」逐项核对
systemd 服务拿不到环境变量 secrets.env 写了 export 前缀 改回纯 KEY=value
私有 provider 配置"消失" 误用了 --reset ./init.sh --restore <备份.tar.gz>
/asset_manager、自定义工具不生效 资产/配置未同步 /reload，或重跑 ./init.sh
