首页 / 应用实践 / 技巧分享

本文是可直接落地的使用技巧，对应内部「参考实现」技巧篇（图片输入 / 资产快捷启动 / 网关模型选择 / 插件扩展）在 opencode 定制版上的表达。每条标注依赖能力与真实性来源，避免「看起来能用、其实没装」的错觉。

图例：

  • 🟢 定制增强——opencode 定制版（本仓库 .opencode/）提供的能力；
  • 🔵 上游原生——opencode 原生能力，配好即可用；
  • 🟡 定制命令 + 插件资产——命令内置在本仓库，执行依赖对应插件资产的技能与凭据。

1. 图片 / Office 文档直接丢给模型 🔵

做法：在 TUI 输入框直接粘贴剪贴板里的图片（快捷键触发），或引用本地图片 / Office 文件让 Agent 用 read 工具读取。

  • TUI 支持从剪贴板粘贴图片进 prompt；read 工具本身支持 JPEG / PNG / GIF / WebP，以及 .docx / .xlsx / .pptx / .odt / .ods / .odp。
  • 截图报错、贴设计稿、贴表格给 Agent 分析，比手敲描述省事。

注意（Linux）：剪贴板读图依赖系统工具（Wayland 的 wl-paste 或 X11 的 xclip）。两者都缺时粘贴无图，安装 wl-clipboard 或 xclip 即可。

2. jira / gerrit / kb 查询变一句话 🟡

做法：把「查 Issue / 搜变更 / 找知识库」变成一条斜杠命令，Agent 自动调用对应技能：

/jira_get_issue PROJ-123          # 读 Issue 详情（含变更历史）
/jira_new_task 修复登录超时        # 新建任务（父任务/经办人脚本自动补全）
/gerrit_search_changes message:登录 status:open
/gerrit_get_file Monitor/x/src src/main.c
/kb_search 老化测试
/kb_get_page 12345678

依赖：命令已内置在 .opencode/command/；执行由 jira-cli / gerrit-cli / kb-cli 技能（随插件资产分发）完成，凭据配在 ~/.config/secrets.env（JIRA_TOKEN / GERRIT_SSH_HOST / CONFLUENCE_API_TOKEN）。未配置时命令可用但会因缺凭据失败——先看排障 FAQ。

为什么好用：查询类工作无需解释怎么做，命令模板已经固化了参数与输出格式，也避免每次重复描述。

3. 长任务丢后台，不占对话 🟢

做法：构建、全量测试、长时间监控这类命令交给 background-task，Agent 后台执行、输出落盘，完成后只回收摘要：

让 Agent：后台跑 bun run build，完成后告诉我结果
  • 输出写入 .opencode/tasks/<id>.log，不把大段日志灌进对话上下文；
  • 任务记录 exit_code 与 finished_at，完成时发桌面通知（notify-send）；
  • 随时 list 看状态、output <id> 看输出、stop <id> 停任务。

注意：桌面通知在无图形会话或缺少 notify-send 时静默跳过（不报错）；可用 MA_NO_DESKTOP_NOTIFY=1 关闭。

4. 拿准 /compact 时机 🔵

做法：换任务前压缩上下文，别让旧历史每轮重复付费。

时机 动作
长会话、明显变慢 /compact（保留近期原文）
上下文快满 / 报超限 /compact，或调整 compaction 策略
切换到不相关的新任务 直接 /new 开新会话，比压缩更干净
压缩后继续原计划 /compact_run <计划>

原理：预算以模型 limit.context 为基准触发自动压缩。私有模型缺 limit 时不会触发——./init.sh 会为私有模型自动注入 context=200000 / output=32768 的有效预算，见省 token 与上下文管理。

5. 场景 + reference 沉淀结论 🟢

做法：把「一次探索得到的结论」写进工作场景的 reference/，下次直接检索，而不是重新问一遍。

/workscene find 认证流程            # 全文检索参考知识
  • 场景 = 领域知识库：reference/{architecture,research,bugfixed,requirements} + memory/；
  • 把架构决策、排障结论、需求要点归档其中；跨会话可用 workscene find <关键词> 找回；
  • 与 memory（跨会话偏好/模式）配合：reference 放领域知识，memory 放稳定偏好与经验。

为什么：结论落盘后不再消耗探索 token，也回答了「上次那个结论在哪」的问题。详见工作场景。

6. 模型快切（轻活快档、重活强档）🟢

做法：让探索 / 摘要走小模型，重活再上主力模型。

方式 操作
循环最近模型 F2 / Shift+F2
打开模型选择器 Ctrl+X m（<leader>m）
启动时指定 opencode -m <provider>/<model>
永久默认 opencode.json 的 model / small_model

要点：本次增强——子代理 frontmatter 写 model: small 即解析到 small_model（解析不到回退父模型），explorer 已默认挂载。轻量探索因此天然走快档，无需手动切。TUI 的模型选择器分组可在 tui.json 的 model_tabs 配置。

7. 资产像包管理器一样用 🟢

做法：常用工具 / 技能 / 启动器按需拉取，而不是预先装一大堆。

asset list @skill                  # 查看可用资产（按类型过滤）
asset pull @skill/docx             # 拉到本地缓存
asset setup @skill/docx            # 部署到项目 .opencode/skills/（目录扫描即生效）
asset run @tool/oc-lark            # 运行工具 / 启动器
  • TUI 里输入 / 选 /asset_manager，用 ✅/⬜ 列表交互拉取，不用记命令；
  • 资产是「打包环境」：一个 @launcher / @tool 就能带起整套配置与工作流；优先级为 项目级 > mirror 本地镜像 > 远程仓库；
  • 依赖自动解析：pull @launcher/xxx 会按 meta.json 的 requires 拉取依赖组件。

详见资产与常用命令。

8. 并行任务用子代理 + worktree 隔离 🟢

做法：多条并行的独立工作，用子代理并行推进，需要改代码时用 git worktree 隔离工作区。

  • 子代理在独立上下文完成，只回传结论（省 token）；并发上限由 subagent_max_concurrency 控制（默认 4，范围 1-8），防止并发风暴；
  • git-worktree 提供 create / list / merge / remove：merge 走「rebase → 预检 → fast-forward → 可选 cleanup」，冲突时自动 abort 不动主树；remove 在树脏或分支未合并时拒绝删除（除非 force）。

为什么：并行不是为了更快地制造冲突——隔离 + 守护让「多线开工」不会污染主分支。详见隔离执行与 worktree 与子代理与编排。

一页纸记住

  1. 少解释、多命令——jira / gerrit / kb / plan / todo 都有模板化入口；
  2. 过程放子代理、大输出放后台、结论落 reference——主上下文只留决策；
  3. 成本看分档——探索走 small_model，重活再上强模型；
  4. 长会话及时压、换任务开新会话；
  5. 并行走 worktree，合回走 merge 守护。
