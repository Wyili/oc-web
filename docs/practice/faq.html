一、高频问题速查表

# 现象 可能原因 解决
1 opencode: command not found 新终端未生效 / PATH 缺目录 source ~/.bashrc 或重开终端；确认 ~/.local/bin、~/.config/opencode/bin 在 PATH
2 模型报 401 /「未提供认证凭据」 secrets.env 缺对应 key，或未 source grep '^OPENAI_API_KEY=' ~/.config/secrets.env；set -a; source ~/.config/secrets.env; set +a；核对 provider baseURL
3 provider not configured / 模型不可用 provider 未配置或名称写错 在 opencode.json 的 provider 字段配 npm 包 + baseURL + apiKey: "{env:XXX}"
4 改配置 / 加技能后不生效 运行中未重载 会话内 /reload；命令/技能 symlink 新增即生效，但需刷新
5 工具调用被拒绝 permission 规则过严，或 run 档位为 strict / balanced 非交互改用 opencode run --mode accept-edits（或 trust）；--auto ≡ trust；显式拒绝的操作不会放行
6 上下文过大 / 响应变慢 历史与工具输出累积超预算 /compact、/clear，或调整 compaction；换任务用 /new
7 自动压缩从不触发（私有模型） 模型缺 limit.context，阈值算不出 ./init.sh 会为私有模型注入 200000/32768；或用 --force 重建后再 --reload
8 jira / gerrit / kb 插件不工作 对应环境变量缺失 配 JIRA_TOKEN / GERRIT_SSH_HOST / CONFLUENCE_API_TOKEN；/plugins list 查状态
9 gerrit 命令报认证/SSH 失败 公钥未配到 Gerrit 服务端 把 ~/.ssh/id_*.pub 配到 Gerrit（Settings → SSH Keys）；确认 GERRIT_SSH_HOST 与 ~/.ssh/config
10 初始化报 bun not found 缺 bun 运行时 init.sh 会自动安装；失败则 curl -fsSL https://bun.sh/install \| bash 后重试
11 拉取代码后仍是旧版本 二进制未重编译 cd ~/opencode && git pull && opencode init --build
12 资产拉取失败 资产仓库不可达 / 源配错 asset list 确认；检查 .opencode/opencode.jsonc 的 assets.repo 或 OPENCODE_ASSETS_REPO
13 模型列表过旧 / 缺新模型 本地缓存旧 opencode models --refresh
14 MCP 服务器连不上 command/args 配错或进程起不来 opencode mcp 看状态；核对 mcp.servers；用 @tool/mcp-inspector 调试
15 脚本 / cron / systemd 拿不到密钥 非交互 shell 提前 return secrets.env 的 source 必须在 bashrc 交互守卫之前；systemd 用 EnvironmentFile 指向 secrets.env
16 粘贴图片进 prompt 没反应 Linux 缺剪贴板读图工具 装 wl-clipboard（Wayland）或 xclip（X11）；或改为引用本地图片文件让 read 读取
17 后台任务完成没有桌面通知 无图形会话或缺 notify-send 通知静默跳过不影响功能；确认 MA_NO_DESKTOP_NOTIFY 未设为 1，需要时装 libnotify-bin
18 worktree remove 被拒绝 树有未提交改动 / 分支未合并 先 commit 或 stash，或对分支执行 merge；确需强制删除才用 force=true
19 换场景后 AI 找不到已有知识 场景未激活 / reference 为空 workscene activate <name> 切换场景；用 workscene find <关键词> 确认条目存在
20 同一操作反复失败仍不停手 未先诊断就重试 见快速定位问题：连续失败 3 次先停下、上报阻塞，别重复烧无效轮次
21 opencode upgrade 后定制功能消失 官方升级覆盖了定制版二进制 定制版请用 git pull && opencode init --build 重建，不要用 upgrade
22 压缩后关键上下文丢失 压缩只保留近期 token，过程信息被折叠 压缩前把结论写入工作场景 reference/ 或记忆，或用 /compact_run <计划> 带着计划继续
23 TUI 模型选择器缺少分组 / 常用模型难找 tui.json 未配置 model_tabs 在 tui.json 配 model_tabs.tabs（如 favorites / recent / local）

二、密钥与认证（1 号杀手）

密钥统一放 ~/.config/secrets.env（0600，非 git），由 ~/.bashrc 顶部 set -a; source …; set +a 注入。三条最常见坑：

  1. 写了 export 前缀。secrets.env 必须是纯 KEY=value，一行一个、不加引号、不加 export。带 export 时 systemd EnvironmentFile 解析失败 → 服务拿不到变量 → 401。
  2. source 位置在交互守卫之后。~/.bashrc 开头有 case $- in *i*) *) return;; esac，非交互 shell 会提前 return。source secrets.env 必须放在守卫之前（init.sh 已按此插入），否则脚本 / cron 拿不到。
  3. 没在新终端生效。改动后 source ~/.bashrc，或新开终端。

自检：

set -a; source ~/.config/secrets.env; set +a && env | grep -c '^OPENAI_API_KEY='   # 输出 1 即就绪
opencode debug config        # 确认所用 provider 的 apiKey 非空（空 = 未配置或未 source）
opencode run "回复ok"         # 实际调用验证；报 401 回查密钥

迁移换机后：密钥与私有 provider 不进 git。新建 secrets.env 填入真实值，并从旧机拷贝 ~/.config/opencode/opencode.json（含私有 provider），再 source ~/.bashrc。

三、安装与环境

现象 原因 解决
init 报 git not found 系统无 git 安装 git 后重跑 ./init.sh
python3 not found 警告 插件脚本与私有配置合并需要 python3 sudo apt install python3（缺 python3 时 --force 合并会退化）
编译离线失败 拉不到 models.dev 模型清单 预置缓存 ~/.cache/opencode/models.json，或联网编译
换机后命令全丢 PATH / wrapper 未部署 跑 ./init.sh（自动补 PATH 与 wrapper），再 source ~/.bashrc
--force 后私有 provider 丢了 期望被 --force 覆盖 正常不会丢：--force 会自动保留并备份；--reset 才会清空（先备份到 /tmp/opencode-config-backup/）

备份私有配置：./init.sh --backup → ~/opencode-config-backup-<ts>.tar.gz；还原：./init.sh --restore <备份.tar.gz>。

四、上下文与性能

  • 上下文过大：<leader>c 或 /compact 压缩；调整 compaction（auto / tail_turns / preserve_recent_tokens / reserved）。
  • 单次工具输出吞预算：tool_output.max_lines / max_bytes 控制（模板默认 200 行 / 8KB，超限写文件 + 预览）。
  • 大日志 / 长测试：交给后台任务，输出落盘 .opencode/tasks/<id>.log，不灌入对话。
  • 反复失败重试：同一操作连续失败 3 次先停下诊断，别重复烧无效轮次。

五、技能与命令不触发的排查顺序

  1. 是否加载——/reload 刷新；命令/技能目录 symlink 新增即生效，但运行中需刷新。
  2. 是否在生效范围——项目级技能放 <项目>/.opencode/skills/（只在该项目生效）；全局放 ~/.config/opencode/ 或 skills.paths。
  3. 是否可被匹配——技能靠 description 自动匹配，把触发条件写进描述（「当 X 时使用…」），空泛描述不会被选中。
  4. 凭据是否就位——jira / gerrit / kb 类命令即使加载成功，也需对应环境变量才能跑通。

六、常用自检命令（照抄）

检查目标 命令
命令是否就位 command -v opencode && ls -l ~/.local/bin/opencode
配置是否合法 python3 -m json.tool ~/.config/opencode/opencode.json > /dev/null && echo ok
密钥是否加载 grep -oE '^[A-Z_]+=' ~/.config/secrets.env \| tr -d '='
provider / apiKey 解析 opencode debug config（确认 apiKey 非空）
实际调用是否通 opencode run "回复ok" --model <provider>/<model>
详细日志 opencode --print-logs --log-level DEBUG
模型缓存是否过旧 opencode models --refresh
会话与成本趋势 opencode session / opencode stats --days 7
资产源是否可达 asset list
源码/二进制是否同步 opencode init --build（拉代码后必做）

七、常见误区与正解

误区 后果 正解
在 secrets.env 里写 export KEY=value systemd 解析失败、服务 401 只用纯 KEY=value，由 bashrc 的 set -a 自动导出
把密钥直接写进 ~/.bashrc bashrc 是 644 明文、systemd 不加载 统一放 secrets.env（0600），bashrc 只 source
以为 --force 会丢私有 provider 不敢用 --force 重建配置 --force 自动保留并备份；只有 --reset 才清空（先备份到 /tmp）
整段 cat 大文件 / 大日志 单次吞掉巨额预算 先 grep 定位行号，再按 offset/limit 读片段
拉完代码不重编译 跑的还是旧二进制 git pull && opencode init --build
排查时直接 --reset 清空全部私有配置 先 --backup，或只改必要项；--reset 会先备份到 /tmp
同一操作反复重试 重复输出入上下文、烧 token 失败先诊断（见快速定位问题），3 次即停并上报

八、最短排查路径（30 秒走一遍）

遇到「不工作」先按顺序过一遍，多数问题在前两步解决：

  1. 刷新——/reload（配置 / 技能是否生效）；
  2. 看配置——opencode debug config（provider 是否在、apiKey 是否为空）；
  3. 认证失败——查 secrets.env 是否有对应 key，set -a; source …; set +a 后重试；
  4. 上下文过大——/compact 或 /new；
  5. 权限被拒——调整 permission 规则；非交互场景用 opencode run --mode accept-edits（或 trust），或加 --auto；
  6. 仍不明——opencode --print-logs --log-level DEBUG 拿到日志，再按快速定位问题分类事实与假设。

记忆点：先刷配置（/reload）→ 再验凭据（debug config）→ 后看上下文与权限 → 最后上日志。顺序对了，绝大多数「玄学问题」都能在几步内定位。
