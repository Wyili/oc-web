首页 / 应用实践 / 实时思考与 UI 设计

参考实现在两个体验方向上有系统性设计：思考过程实时可见（流式推理、子代理过程、任务进度）与界面把状态说清楚（面板、角标、通知、作品卡）。本文归纳其机制、对照 opencode 现状，列出值得借鉴的点。

一、为什么思考过程要实时可见

  • 信任与可控：用户看得见「正在想什么、做到哪一步」，才能及时纠偏（中止、追加指令、调整方向）。
  • 排障：卡住时一眼看出卡在轮次、工具还是模型。
  • 演示与教学：过程本身就是内容——「怎么想的」比「想出了什么」更有参考价值。

思考过程实时输出的三个要素

要素 说明 体验目标
流式 推理内容随生成实时出现，而不是等完成才显示 无「假死」感
可折叠 默认收起（hide）、思考中自动展开、完成收起为一行；一键切 show 不挤占正文，需要时可追
可定位 主代理动作、子代理过程、工具调用分别归属、各成条目 多代理并行时可观测

二、参考实现的机制清单

# 机制 要点
1 流式推理展示 推理随思考实时展开；完成后收起为单行；有可见度档位设置
2 子代理「过程详情」卡 实时展开子代理的轮次 / 所用模型 / 工具调用 / 思考摘要
3 编排态展示 主代理动作行 + 并行子代理列表（每个任务一行状态：运行中/完成/等待）
4 任务进度（TaskBanner） 执行中实时进度；执行前计划/待办全文预览 + 隔离执行开关
5 完成通知 通知卡片（退出码、耗时）+ 桌面通知（OSC 99 转义序列，Kitty/iTerm2/WezTerm 等原生弹窗）
6 工作流运行卡 聊天区实时进度卡；点开节点明细与输入输出；{ } 查看 YAML 源码；失败自动展开标红
7 跨项目会话面板 一屏管理所有工作区会话：运行状态徽标、待答角标
8 作品卡 markdown / mermaid 流程图 / ECharts 图表 / SVG / 交互式 HTML 原地渲染
9 输入增强 图片粘贴与拖拽、语音输入、快捷用语、/ 与 @ 补全

方向 opencode 现状 证据

四、可借鉴清单（建议）

借鉴点 价值 落点建议
子代理「过程详情」可展开卡 多代理并行时过程透明，排障更快 TUI：由 SubagentFooter 扩展；或 Web 端会话侧栏
后台任务完成 → 会话内可见卡片 当前只有桌面通知，切回终端才能看到结果 TUI 事件流 / lifecycle-hooks 注入
任务/计划进度可视化 plan/todo 执行进度一目了然 plan 工具状态 + TUI 渲染
作品卡渲染（mermaid/ECharts/SVG） 产出「可看」而非「可读」 Web 端优先，TUI 评估
通知中心（未读角标/跨项目会话） 多会话/daemon 场景的注意力管理 依赖上游会话面板能力，评估
思考展开策略细化 如「思考时自动展开、完成后收起」之外的档位（敏感度分级） 已有 show/hide 基础上小步走

以上为借鉴方向而非承诺项：多数需要 TUI/Web 端改动，建议按「收益 × 成本」逐项评估后再进 backlog。

五、原则总结（跨实现通用）

  1. 状态可见——三个问题随时有答案：在运行吗？到哪步了？需要我吗？
  2. 渐进披露——默认收起、需要时展开；详情永远比默认视图深一层。
  3. 主动触达——完成与阻塞主动通知（桌面通知 + 会话卡片），不让用户盯着屏幕等。
  4. 输入效率——粘贴、拖拽、快捷用语、补全，让「表达意图」的成本尽可能低。
