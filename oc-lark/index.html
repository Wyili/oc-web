SETUP GUIDE · 配置指南

从本地开始，
三步接通。

GitHub Pages 只托管静态页面，服务运行在你控制的环境中。

1

获取与初始化

从资产目录获取开发版（asset pull @tool/oc-lark），执行 ./oc-lark setup 初始化工作目录 / serve 地址 / 权限模式。

2

配置飞书凭证

在 ~/.config/secrets.env 填写飞书应用凭证，启用机器人能力、消息事件与 WebSocket 长连接，凭证只放后端。

3

启动与验证

./oc-lark start 自动拉起 serve + bridge；用 status / doctor 自检，在飞书发送消息验证连接。

安装与启动 
$ asset pull @tool/oc-lark  # 获取开发版
$ ./oc-lark setup           # 初始化
$ ./oc-lark start           # 启动服务
$ ./oc-lark status && ./oc-lark doctor

配置与发布状态

关键配置在 ~/.config/secrets.env：

FEISHU_APP_ID / FEISHU_APP_SECRET — 飞书凭证SERVE_BASE_URL — 默认 127.0.0.1:28080WEB_PORT — 控制台，默认 28083PERMISSION_MODE — strict / balanced / trust

当前为资产开发版（v0.5.6）；正式版仍在规划中，真实飞书环境联调持续进行。

飞书与 OpenCode 凭证只放后端，勿写入页面或暴露 OpenCode Server。

FAQ · 常见问题

开始之前，
先把边界说清楚。

oc-lark 是 OpenCode 的替代品吗？

不是。它是连接飞书与原生 opencode serve 的 Python 服务，执行仍由 OpenCode Server 完成。

能把后端部署到 GitHub Pages 吗？

不能。GitHub Pages 只托管静态页面，后端需运行在你的环境中。

WebSocket 和 SSE 分别做什么？

飞书 WebSocket 收消息，OpenCode SSE 推送事件，oc-lark 负责桥接。

API 地址和 token 会被保存吗？

输入值仅在浏览器运行时使用，刷新即清空。请使用 HTTPS、最小权限和短时 token。

目前支持多 Agent、Nexus 或云托管吗？

当前不接入这些能力，页面仅介绍已实现的连接与交互。
